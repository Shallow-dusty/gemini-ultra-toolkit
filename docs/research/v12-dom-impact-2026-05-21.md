### 1.2 二级风险（模块级失效）

#### D. Sidebar 容器
- **代码位置**：`src/native_ui.js:107` `getSidebar()`
- **旧选择器**：`.sidenav-with-history-container, bard-sidenav, nav[role="navigation"]`
- **新版实际**：`<nav aria-label="Side Navigation" role="navigation">`（ref=e34/e38）
  - 内部嵌套：`nav[aria-label="Main actions menu"]`、`nav[aria-label="Additional actions menu"]` 等多个子 nav
- **结论**：⚠️ **前两个精确选择器失效**（`.sidenav-with-history-container` 和 `bard-sidenav` 都不存在），但兜底 `nav[role="navigation"]` 仍能命中
- **风险**：`_findFirst` 会返回第一个 `<nav>`，可能是子 nav 而不是外层容器 → 注入位置可能错
- **推荐新选择器**：`nav[aria-label="Side Navigation"]` (最精确) → 兜底 `nav[role="navigation"]`

#### E. Input area 容器
- **代码位置**：`src/native_ui.js:115` `getInputArea()`
- **旧选择器**：`input-area-v2, .input-area-container, .bottom-container`
- **新版实际**：输入区是 `group [ref=e161]`，里面是 `textbox [aria-label="Enter a prompt for Gemini"]`。没有 `input-area-v2` web component 标签，没有 `.input-area-container` 类
- **结论**：❌ **三个选择器全部失效，模块（prompt-vault / ui-tweaks / default-model）的 native UI 注入会全部 broken**
- **推荐新选择器**：找到 `textbox[aria-label="Enter a prompt for Gemini"]` 的祖先 `<group>` 或 `<form>` 容器作为锚点。需要在 DOM 里 trace 一下实际 tag（accessibility tree 看不到原 DOM tag）

#### F. Chat header / 标题容器
- **代码位置**：`src/native_ui.js:122` `getChatHeader()`
- **旧选择器**：`.conversation-title-container, span.conversation-title, h1.conversation-title, [data-test-id="conversation-title"]`
- **新版实际**：
  - chat 详情页有 `heading "Conversation with Gemini" [level=1]`（这是 ARIA 标题，不一定有 conversation-title 类）
  - 但**顶部对话操作按钮**改名了：`button [aria-label="Open menu for conversation actions"]` (more_vert)，是新的"三点菜单"
- **结论**：❌ **四个选择器全部疑似失效**。Export 模块的注入点（在 chat header 旁加 📤 按钮）需要重新定锚
- **推荐新选择器**：`button[aria-label="Open menu for conversation actions"]` 或它的父容器（顶部条）

#### G. Model switch 按钮
- **代码位置**：`src/native_ui.js:131` `getModelSwitch()`
- **旧选择器**：`button.input-area-switch, [data-test-id="bard-mode-menu-button"]`
- **新版实际**：`button [aria-label="Open mode picker"]`，里面文本是 "Flash" 加 `keyboard_arrow_down` 图标
- **结论**：❌ **两个选择器都失效**，`bard-mode-menu-button` 这个 data-test-id 已经被 Google 改了
- **推荐新选择器**：`button[aria-label="Open mode picker"]`
- **关联影响**：counter 模块的模型检测（`MODEL_DETECT_MAP`）需要从这个按钮的子文本读模型名（"Flash" / "Pro" / "Thinking" 等）

#### H. 模型识别 `MODEL_DETECT_MAP`
- **代码位置**：`src/modules/counter.js`、`lib/model_config.js`
- **旧 i18n keywords**：`Flash` / `Thinking` / `Pro` (EN)，加 `高速` / `빠른` / `사고` 等多语言
- **新版实际**：mode picker 当前显示 `Flash`，model 选项的具体子菜单未点开（要 hover/click 才看到）
- **结论**：⚠️ **格式应该兼容（仍是英文 short name），但需要点开菜单确认实际选项 list**。订阅级别"Pro"现在显示在用户名旁（侧栏底部），不是 header 顶部
- **下一步**：v12 改造时点开 mode picker 拿完整菜单 snapshot

#### I. Batch delete - 对话三点菜单
- **代码位置**：`src/modules/batch_delete.js` 模拟 "三点菜单 → 删除 → 确认" 链
- **新版实际**：顶部 `button[aria-label="Open menu for conversation actions"]` (more_vert) 替代了旧的对话 hover 菜单
  - **未确认**：侧栏每个 chat 是否还能 hover 出三点菜单。当前 snapshot 没看到（chat 列表只显示 link，没有 menu button）
- **结论**：⚠️ **大概率需要重写**。新版的对话操作可能只能从顶部 more_vert 进入，不再有 hover-on-row 菜单
- **下一步**：v12 改造时 hover 侧栏 chat 看是否有 hover-action

#### J. Default model - 模型选项 `data-test-id`
- **代码位置**：`src/modules/default_model.js` 用 `data-test-id` 选择模型菜单项
- **新版实际**：menu picker 未展开，无法看到选项的实际属性
- **结论**：⚠️ **未确认**，但 `bard-mode-menu-button` 这种 data-test-id 已经被废，菜单项的 data-test-id 也很可能换名
- **下一步**：v12 改造时点开 mode picker，记录每个选项的实际 selector

#### K. Folders - 侧栏链接 hover + drag
- **代码位置**：`src/modules/folders.js`
- **新版实际**：侧栏 chat 现在是 `<a href="/app/<id>"><generic>Title</generic></a>`，仍然能注入颜色圆点（folder markers）
- **drag and drop**：未确认（要交互测试）
- **结论**：⚠️ **颜色圆点注入应该 OK，拖拽行为需要验证**

## 3. 大版本策略建议

### 选项 A：小补丁式修复
- 只更新 `src/native_ui.js` 的 4 个 getter（sidebar/inputArea/chatHeader/modelSwitch）+ counter/batch_delete/default_model 的选择器
- 工作量：~1 天
- 缺点：下次 Google 再改版还要再改一遍

### 选项 B：引入 GeminiAdapter 抽象层（推荐 ⭐）
- 新建 `src/adapters/gemini.js`，把所有 DOM 耦合点集中到一个文件
  - 接口：`getSidebar()`, `getInputArea()`, `getChatHeader()`, `getModelSwitch()`, `scanSidebarChats()`, `detectUser()`, `getChatId()`, `getModelDisplayName()`, `getMessageBlocks()`, `getMessageActions()` ...
- 各模块改为通过 adapter 获取 DOM 引用，不再自己写 querySelector
- 下次改版只改 `gemini.js` 一个文件
- 工作量：~3 天（含测试 + 8 模块改造）
- 长期收益巨大

### 选项 C：大重写
- 不必要。一二级风险点其实没那么多，二级风险全部在 native_ui.js + 4 个模块里集中可控

**强烈推荐 B**：v12 是难得的窗口期，把 DOM 耦合点抽出来。
